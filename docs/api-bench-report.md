# 노래 생성 API 벤치마크 보고서 (T1)

> 설계 §7.3, §11-T1 · 도구: `tools/api-bench/` (실행 방법은 `tools/api-bench/README.md`)
> **상태: 미실행 - API 키 필요** (`FAL_KEY`, `MUREKA_API_KEY` 둘 다 없음, 2026-10-29)
> 아래 결과 표는 비어 있다. 측정값은 실제로 실행한 뒤에만 채운다.

## 1. 방법

- 대상 공급자 3종. 서버 어댑터(`server/app/providers/music`)를 그대로 호출한다.

  | 공급자 | 엔드포인트 | 입력 |
  |---|---|---|
  | minimax | fal `fal-ai/minimax-music/v2.6` | 스타일 프롬프트 + 가사 |
  | mureka | `POST /v1/song/generate` (model `auto`, n=1) | 스타일 프롬프트 + 가사 |
  | acestep | fal `fal-ai/ace-step` | 장르 태그 + 가사 + 길이 |

- 샘플 가사 3종 (§7.2 규칙을 따르는 창작 가사, `tools/api-bench/samples/`):

  | 샘플 | 스타일 프리셋 | 소재 |
  |---|---|---|
  | `kids.txt` | 동요 | 서울→강릉, 아침 |
  | `city_pop.txt` | 시티팝 | 강변북로→춘천, 저녁 |
  | `acoustic.txt` | 어쿠스틱 | 대전→전주, 비 오는 오후 |

- 요청 길이는 75초 (§7.3 60~90초). 길이 입력이 있는 공급자는 acestep뿐이므로 실제 길이를 따로 기록한다.
- 실행: 3 공급자 × 3 샘플 × N회 (실패율을 보려면 `--repeat 3` 권장).
  - 공급자끼리는 동시에 실행한다.
  - 한 공급자 안에서는 순서대로 실행한다.
- 자동 기록 항목:

  | 항목 | 정의 |
  |---|---|
  | 생성 시간 | 제출부터 완료 응답까지. 폴링 간격 5초만큼 오차가 있다 |
  | 곡 실제 길이 | ffprobe로 읽은 값 |
  | 비용 | 공개 가격표로 계산한 값. 청구액이 아니며, 성공한 곡만 계산한다 |
  | 성공/실패 | 실패면 오류 메시지를 남긴다 |
  | 섹션 타이밍 | 후렴 구간 메타데이터 유무와 그 값 |
  | 곡 파일 | 듣기용으로 저장한다 |

- 사람이 듣고 채우는 항목: 한국어 발음 1~5, 음질 1~5, 메모 (가사 구조 준수 여부 등).

## 2. 채점 기준

| 점수 | 한국어 발음 정확도 | 음질 |
|---|---|---|
| 5 | 가사를 보지 않고도 전부 받아쓸 수 있다 | 잡음·왜곡이 없고 스타일 프리셋과 맞는다 |
| 4 | 한두 단어가 뭉개진다 | 작은 아티팩트가 있고 스타일은 맞는다 |
| 3 | 절반 이상 알아듣는다. 음절 누락이나 외국어 억양이 있다 | 들을 만하다. 아티팩트가 뚜렷하거나 스타일이 일부만 맞는다 |
| 2 | 대부분 알아듣기 어렵다 | 왜곡이나 끊김이 잦다 |
| 1 | 한국어로 들리지 않거나 가사를 무시한다 | 쓸 수 없다 |

- 공급자별 9곡(1회 반복 기준)을 같은 사람이 같은 기기로 듣는다.
- 각 점수는 평균을 낸다.

**결정 기준** (우선순위 순):
1. 한국어 발음 평균 3.5 이상
2. 실패율
3. 생성 시간 (도착 전 READY, §7.1. 서버 제한 5분)
4. 섹션 타이밍 메타데이터 (§7.4 CALL 클립 위치)
5. 곡당 비용

## 5. 잠정 선택 — 공개 정보 기반, 측정 아님

> 아래는 **공개 문서·가격만 보고 고른 잠정안**이다. 생성 시간, 실패율, 한국어 발음, 음질은 아직 측정하지 않았다.
> 벤치마크를 실행한 뒤 이 절을 결과로 다시 쓴다. 그 전까지 서버 기본값은 `MUSIC_PROVIDER=fake`이다.

**기본: mureka (잠정)**
- 문서상 결과에 가사 섹션별 시작·끝 시각(`lyrics_sections`)을 준다. 그래서 CALL 클립을 실제 첫 후렴 뒤에 넣을 수 있다 (§7.4). minimax·acestep(fal)은 문서상 출력이 오디오 URL(acestep은 seed·tags·lyrics 포함)뿐이라 40% 고정 비율로 대체해야 한다.
- 확장 로드맵의 가족 목소리 보컬(보컬 클론, §14)과 같은 공급자다.
- 단점:
  - 공개가가 셋 중 가장 높다 ($0.225, 미확인).
  - 곡 길이를 지정하는 입력이 없다.

**예비: minimax (잠정)**
- fal 큐를 거치므로 mureka와 계정·인프라가 분리되어 있어, 장애가 겹칠 가능성이 낮다.
- 입력 형식이 같다 (스타일 프롬프트 + 태그 가사).
- 공개가 $0.15로 mureka보다 싸다.
- 단점:
  - 곡 길이 입력이 없다.
  - 섹션 타이밍을 주지 않는다.

**acestep**은 공개가가 가장 낮고(약 $0.015) 길이를 지정할 수 있다.
- ACE-Step README는 한국어를 "top 10 well-performing languages"에 넣는다.
- 오픈 모델이라 품질 편차가 클 수 있어 측정 전에는 기본으로 두지 않는다.
- 측정에서 한국어 발음이 기준을 넘으면 비용 면에서 기본 후보가 된다.

## 5-1. ACE-Step 1.5 로컬 실행 (2026-11-03, 유료 API 대신)

- 환경: 데스크탑 RTX 5070 Ti 16GB, Windows 11. ACE-Step 1.5 (MIT, `github.com/ace-step/ACE-Step-1.5`, 커밋 ca1e85f)를 `~/ai/ACE-Step-1.5`에 `uv sync`로 설치 (PyTorch 2.7.1+cu128, sm_120 지원 확인). 모델 자동 다운로드 9.4GB.
- 구성: 기본값 DiT `acestep-v15-turbo`(2B), LM `acestep-5Hz-lm-1.7B`, GPU 자동 등급 tier6a (INT8 양자화). 추론 8스텝, 75초, `vocal_language=ko`, 프롬프트는 서버 `STYLE_PROMPTS`.
- 실행: `acestep-api --host 127.0.0.1 --port 8001` (REST: `POST /release_task` → `POST /query_result` 폴링 → `GET /v1/audio`). Windows에서는 **`PYTHONUTF8=1`** 이 없으면 cp949 인코딩 오류로 모든 작업이 실패하고, **ffmpeg가 PATH에 있어야** mp3 저장이 된다.
- 결과 (요청부터 완료 응답까지, 1초 폴링 포함):

  | 샘플 | plain (thinking 끔) | think (LM 계획) | 비고 |
  |---|---|---|---|
  | 동요 | 51.5초 (첫 곡: 모델 로딩 포함) | 24.7초 | |
  | 시티팝 | 12.3초 | 25.4초 | |
  | 어쿠스틱 | 10.5초 | 23.5초 | |

  모든 곡 길이 정확히 75.0초 (길이 지정 지원), 결과에 bpm·keyscale·박자 메타데이터. 후렴 구간 시각은 주지 않는다 → CALL 클립은 40% 대체 규칙.
- **청취 평가(한국어 발음·음질 1~5, plain vs think)는 사용자가 듣고 채운다** — 미기록.
- 데모 타이밍 영향: 서버 전체(가사 + 노래 11~25초 + 믹싱 약 10초)가 지금 데모 시나리오의 'ETA 10분 → 도착' 실제 약 20초를 넘는다 → 데모 시나리오의 느린 구간을 늘리거나 트리거를 앞당겨야 한다 (§7.1).

## 6. 실행 후 할 일

1. 키를 설정하고 실행한다: `python tools/api-bench/bench.py --repeat 3`
2. `audio/`의 곡을 듣고 `results.csv`의 점수 열을 채운 뒤, 3절 표를 채운다.
3. 2절 기준으로 5절의 기본·예비 공급자를 확정한다. 그 값을 서버 `MUSIC_PROVIDER`에 반영하고, 설계 §7.3도 갱신한다.
4. 섹션 타이밍 결과로 설계 §7.4의 `[확인 필요]` 공급자별 타이밍 메타데이터 유무를 해소한다.
