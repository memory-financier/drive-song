# 데모 영상 시나리오 (T12)

> 설계 §11-T12. "서울→강릉" 데모 모드 + 가족 클립 + 도착 시 자동 재생 흐름을 1분 내외로 촬영하는 절차.
> 2026-10-29 휴대폰 에뮬레이터(Medium_Phone_API_36)와 fake 공급자 서버로 깨끗한 설치부터 끝까지 재현했다.
> 아래 시각은 그때 잰 값이다 (호스트 PC 부하에 따라 몇 초 달라질 수 있다).

## 1. 영상 흐름 (약 60초)

| 영상 시각 | 화면 | 보여줄 것 |
|---|---|---|
| 0초 | 설정 → 데모 모드 "서울 → 강릉 (약 3시간)" **재생** → (선택) 주행 제한 시뮬레이션 켜기 → 홈 | 3시간 주행을 1분으로 재생 |
| 약 3초 | 홈: "주행 기록 중 / 도착이 가까워지면 노래를 만들어요" | 주행 기록 |
| 약 36초 | 홈: "노래를 만들고 있어요" | ETA 10분 이내 → 가사·노래 생성 시작 (§7.1) |
| 약 41~55초 | 홈: "노래가 준비됐어요: 강릉 경포해변 가는 길" | 도착 전에 READY |
| 약 56~59초 | 홈: "대기 중 / 재생 중: 강릉 경포해변 가는 길" + 소리 | 도착(P단) 순간 자동 재생 |
| 이후 | 재생 탭 → 보관함 → "가사 보기" | 제목, 정적 커버, 가사(탑승자 호칭 포함) |

- 노래(75초)는 INTRO(출발 인사) → 곡 → 첫 후렴 뒤 CALL(응원 한마디) → 곡 끝 OUTRO(도착 인사) 순서다 (§7.4).
  영상에서 가족 목소리가 들리게 하려면 노래 앞부분(INTRO)과 끝(OUTRO)을 살린다.
- 주행 제한 시뮬레이션을 켜면 주행 중 화면(홈 단순화, 상단 "주행 제한 시뮬레이션 중" 배너)을 보여줄 수 있다.
  데모 모드의 차속은 제한 상태를 바꾸지 않으므로 (§3 참고) 직접 켜야 한다. 도착 후 배너의 **끄기**로 해제한다.
  켠 상태에서도 생성·자동 재생은 똑같이 동작한다 (동네 마트 시나리오로 확인).

## 2. 서버 실행 (fake 공급자, 데모 타이밍)

필요: Python 3.12+, `ffmpeg`/`ffprobe` (PATH).

```bash
cd server
pip install -e ".[dev]"
# 새 데이터 디렉터리 (예전 drive_song.db 는 컬럼이 모자랄 수 있다, server/README.md 참고)
DATA_DIR=./data-demo MUSIC_PROVIDER=fake LLM_PROVIDER=fake GEO_PROVIDER=fake \
FAKE_MUSIC_DELAY_SEC=0 JOB_POLL_INTERVAL_SEC=1 \
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- `FAKE_MUSIC_DELAY_SEC=0 JOB_POLL_INTERVAL_SEC=1` 은 데모용 여유 시간 확보다. 기본값(3초, 5초)으로도 동작했지만
  READY 와 도착 사이 여유가 약 4초뿐이었다 (서버 잡 13~15초 → 앱의 세 번째 폴링). 위 값으로는 앱이 첫째~둘째 폴링
  (생성 시작 후 5~10초)에 READY 를 받아 여유가 약 10~15초였다.
- 확인: `http://127.0.0.1:8000/docs` 가 열리면 된다. 요청 로그는 이 터미널에 찍힌다.

## 3. 앱 빌드·설치

```bash
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"   # Windows Git Bash 예
cd android
./gradlew :app:installDebug                       # 서버가 8000 이 아니면 -PdriveSongApiBaseUrl=http://10.0.2.2:<port>/
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb"
"$ADB" shell pm clear com.drivesong                # 깨끗한 상태에서 시작 (권한도 초기화된다)
"$ADB" shell am start -n com.drivesong/.MainActivity
```

- 기본 서버 주소는 `http://10.0.2.2:8000/` (에뮬레이터에서 본 호스트 PC).
- 서버를 바꾸거나 서버 DB 를 지웠으면 반드시 `pm clear` 한다. 앱의 디바이스 토큰은 이전 서버에만 등록되어 있다.

## 4. 촬영 전 준비 (영상 밖에서 한 번)

1. **가족·녹음** 탭 → **가족 추가**
   - 호칭 프리셋 선택 (예: 첫째), "만 14세 미만 아이예요" 켜기
   - "목소리 수집·이용에 동의해요" + "보호자로서 … 동의해요" 둘 다 체크해야 **등록**이 켜진다 (§8.1)
2. 슬롯 3개 녹음: 출발 인사 / 응원 한마디 / 도착 인사 각각 **녹음** (처음 한 번 마이크 권한 → "While using the app")
   → 최대 5초 뒤 자동 정지 → **미리듣기** → **저장** (서버 `POST /v1/clips 201`).
   - 휴대폰 에뮬레이터 마이크는 기본적으로 무음에 가깝다. 실제 목소리를 넣으려면 에뮬레이터
     Extended controls → Microphone → "Virtual microphone uses host audio input" 을 켜고 PC 마이크로 말한다.
     무음 클립은 믹서가 건너뛰므로 노래에 목소리가 들어가지 않는다 (§5 제약 참고).
3. **탑승자** 탭 → 등록한 가족 체크 (다음 주행에도 유지).
4. **설정** → 노래 스타일 선택(기본 시티팝), "도착하면 자동 재생" 켜짐 확인(기본), **데모 모드** 켜기.
5. **홈** → **주행 기록 시작** → 위치 권한("While using the app"), 알림 권한("Allow").
   주행 기록이 켜져 있어야 시나리오 주행이 기록된다. 상태가 "대기 중" + "주행 기록 끄기" 버튼이면 준비 완료.
6. 리허설: 설정 → "동네 마트 (약 10분)" **재생** (약 22초) → 홈에서 "재생 중: 동네 마트 가는 길" 까지 확인.
   리허설 곡은 재생 탭에서 일시정지한다. 필요하면 설정 → 모든 데이터 삭제 후 1~3을 다시 한다
   (삭제하면 서버의 구성원·클립·노래도 지워진다).

## 5. 촬영

1. 녹화 시작.
   - 화면만: `"$ADB" shell screenrecord --time-limit 120 /sdcard/demo.mp4` → `"$ADB" pull /sdcard/demo.mp4`
     (`screenrecord` 는 소리를 녹음하지 않는다).
   - 소리까지: 에뮬레이터 창을 PC 화면 녹화 도구(OBS 등)로 시스템 소리와 함께 녹화한다.
2. 설정 → "서울 → 강릉 (약 3시간)" **재생** → (선택) 주행 제한 시뮬레이션 켜기 → 곧바로 **홈** 탭.
3. 홈 진행 상태가 §1 표 순서로 바뀌는 것을 그대로 둔다 (조작 없음, 약 60초).
4. "재생 중" 이 되면 (선택) 배너 **끄기** → **재생** 탭 (제목·커버·일시정지) → **보관함** → **가사 보기**.
5. 녹화 종료.

확인용 (영상 밖):
- 서버 로그: `POST /v1/trips/enrich`, `POST /v1/lyrics`, `POST /v1/song-jobs`, `GET /v1/song-jobs/...` (5초 간격), `GET /v1/songs/.../audio`.
- 잡의 clipPlan: `DATA_DIR/drive_song.db` 의 `jobs.clip_plan` 에 INTRO/CALL/OUTRO 클립 id.
  곡 길이가 75초보다 길면 INTRO/OUTRO 클립이 들어간 것이다 (무음 클립뿐이면 정확히 75초).
- 재생 상태: `"$ADB" shell dumpsys media_session | grep -E "state=PlaybackState|description="` → `PLAYING(3)`, 노래 제목.

## 6. 알려진 제약

- **휴대폰 에뮬레이터 vs Pleos Connect 에뮬레이터**
  - 휴대폰 에뮬레이터에는 Car API 가 없어 주행 제한은 "주행 제한 시뮬레이션" 토글로만 바뀐다. 데모 모드의 차속·기어는
    제한 상태에 반영되지 않는다. Pleos 에뮬레이터에서는 실제 `CarUxRestrictions` 를 따르며 아직 기기에서 확인하지 않았다.
  - 분할 화면, 버튼 크기 등 Pleos UI 가이드 확인은 Pleos 에뮬레이터에서 따로 해야 한다.
- **에뮬레이터 마이크**: 기본 입력은 무음(-70dB 안팎)이라 믹서의 게이트·무음 제거 후 남는 소리가 없어 클립이 빠진다
  (흐름은 정상, 노래에 목소리만 없음). §4-2 의 호스트 오디오 입력을 켜야 한다. 처음 녹음은 마이크 준비 지연으로 1~2초만
  녹음된 적이 있다.
- **fake 공급자 vs 실제 키**
  - fake 음악은 ffmpeg 로 만든 화음 반복(가사 없음), fake 가사는 템플릿, fake 지명·날씨는 고정 규칙이다.
    영상에 실제 노래가 필요하면 `MUSIC_PROVIDER`(mureka/minimax/acestep), `LLM_PROVIDER=claude`, `GEO_PROVIDER=live` 와
    키가 필요하다 (`server/README.md`).
  - 데모 시나리오는 ETA 10분 이내 → 도착 구간을 실제 약 20초로 압축한다. 실제 음악 공급자는 생성에 보통 수십 초~수 분이
    걸리고(T1 벤치마크 미측정), live 지명 조회(Nominatim)만 약 8초, Claude 가사도 수 초~수십 초라 **도착 전에 READY 가 되지 않는다**.
    이 경우 도착 시 "노래가 곧 완성돼요" → 완성 알림이 뜨고 자동 재생은 하지 않는다 (§7.1). 실제 공급자로 촬영하려면
    알림을 눌러 재생하는 장면으로 편집하거나, 시나리오를 그대로 두고 생성 대기 구간을 컷 편집해야 한다.
- **타이밍 여유**: 앱은 5초마다 잡을 폴링한다 (§9). 서버 잡이 15초를 넘기면 도착(약 20초)을 놓칠 수 있다.
  믹서 마스터링을 빠르게 고치기 전(커밋 b1adb10)에는 이 PC 에서 잡이 26.6초 걸려 도착 10초 뒤에 READY 가 되었다.
  호스트 PC 가 바쁘면(에뮬레이터 + 빌드 동시 실행 등) 같은 일이 생길 수 있으니 촬영 중에는 빌드를 돌리지 않는다.
- **노래 날짜**: 보관함 날짜는 시나리오 시계 기준이다 (서울→강릉은 09:30 출발 → 약 12:28).
- **데이터 삭제 후 홈 상태 문구**: 삭제 직후 홈 진행 상태가 이전 곡의 "보관함에 저장했어요" 로 남을 수 있다 (다음 주행에서 바뀜).

## 7. 대화 데모 — 가족 목소리 노래 (T19, v0.4)

차 안 대화가 가족 목소리 노래가 되는 흐름(설계 §7.5)을 Pleos 에뮬레이터에서 재현한다. 에뮬레이터 마이크는 무음이라
**데모 모드에서는 마이크 대신 앱에 넣은 데모 대화를 쓴다** (`DemoChunkRecorder`).

### 7.1 데모 음성 (합성 음성 가족, 2026-11-13)
- 가상의 가족(엄마·아빠·첫째) 목소리다. 실제 사람이 말한 녹음이 아니라 합성 음성(TTS)이다.
- 목소리 샘플: Zeroth-Korean (CC BY 4.0, Lucas Jo·Wonkyum Lee), Hugging Face `kresnik/zeroth_korean` 시험 세트의 화자
  132(엄마, 197Hz)·112(아빠, 112Hz)·121(첫째, 231Hz) 발화 하나씩. 첫째는 샘플의 음높이(+5반음)와 음색(포먼트 1.15배)을 올려
  아이 같은 목소리로 만들었다 (WORLD). 합성은 CosyVoice 3 (`Fun-CosyVoice3-0.5B`, Apache-2.0).
  앱의 `assets/demo/NOTICE.txt` 에 출처를 둔다.
- 왜 바꿨나: 이전 데모(화자 147·118·105 의 뉴스 낭독 문장을 이어 붙인 것)는 세 목소리가 비슷하게 들리고 대화 내용이 엉뚱했다.
  지금은 가족 대화 대본(`docs/demo-family-recording.md` 대본의 3명판, 23줄)을 그대로 말한다.
- 대화 `conversation.m4a` (86초, 23줄, 0.6초 간격), 등록 클립(음성 ID, 4.9초): 자기소개 문장.
- 만드는 순서 (CosyVoice 설치본의 venv 로 1·2, voice-lab venv 로 3):
  1. `python tools/demo-conversation/make_tts_family.py <zeroth parquet> <out>` — 대본 23줄과 음성 ID 를 합성하고 대화로 잇는다
  2. `python tools/demo-conversation/tts_regen.py <out> 1,8,9` — 발음이 뭉개진 줄만 후보 3개씩 다시 합성
  3. `python tools/demo-conversation/tts_pick.py <out>` — 받아 적기 글자 오류가 가장 적은 후보로 바꾸고 대화를 다시 잇는다
  4. `ffmpeg` 로 AAC 모노 16kHz 32kbps 로 바꿔 `assets/demo/` 에 넣는다 (음성 ID 는 4.9초로 자른다)
- voice-lab 확인: 화자 23/23 발화 정확, 받아 적기 글자 오류 줄마다 7% 이하, 참고 목소리 엄마 17초·아빠 15초·첫째 17초,
  말소리 음높이 엄마 214Hz·아빠 115Hz·첫째 339Hz.
- 이전 공개 음성 데모를 만든 스크립트는 `tools/demo-conversation/build_demo.py` (지금 앱에는 쓰지 않는다).

### 7.2 서버 (실제 GPU 구성)
ACE-Step(8001), Ollama(11434), voice-lab(8002)를 띄운 뒤 (CLAUDE.md "로컬 GPU 서비스"):

### 7.3 준비 (영상 밖에서 한 번)
1. **설정** → 데모 모드 켜기 → **데모 가족 (합성 음성) 불러오기** → 확인. 엄마·아빠·첫째가 모든 동의(첫째는 보호자 동의)와
   합성 음성 등록 클립으로 등록되고 탑승자로 골라진다 (같은 호칭의 가족은 지우고 새로 만든다).
2. **탑승자** → **대화 담기 (이번 주행)** 켜기 (마이크 권한). 상단에 "대화 담기 켜짐 · 출발하면 녹음해요" 배너.
3. **홈** → 주행 기록 시작 (포그라운드 서비스가 location|microphone 타입이 된다).
- 대화 담기는 이번 주행만 켜진다: 데모를 다시 하려면 2부터 다시.

### 7.4 촬영 흐름 (약 9분, 실측 2026-11-13)
**설정** → 서울 → 강릉 **재생** → **홈**. 대화 담기를 켜고 재생하면 도착 전 10분을 1.25배속(약 7분 40초)으로 느리게 재생한다
(대화 분석·후보 곡 고르기·가족 목소리 변환 시간, `ScenarioPlayer.CONVERSATION_FINALE_SPEED_UP`).

| 시각 | 화면 |
|---|---|
| 0:00 | "● 대화 담는 중 · 끄기" 배너, 주행 기록 중 (데모 대화가 조각으로 담긴다) |
| 0:36 | 도착 10분 전: 녹음을 멈추고 조각 업로드 → "차 안 대화를 가사로 옮기고 있어요" (받아 적기·화자·Gemma 가사) |

### 7.5 알려진 제약
- 데모 대화는 합성 음성(가상의 가족)이다. 가족이 직접 녹음한 대화로 바꾸는 방법은 `docs/demo-family-recording.md` (git 밖 `android/demo-private/` 에 두면 앱이 그것을 먼저 쓴다)
  (`assets/demo/` 파일만 바꾸면 된다, 등록 클립도 같은 화자로).
- 데모 조각은 조각마다 같은 대화 파일을 쓴다: 데모 주행은 노래 생성까지 약 40초라 조각이 하나뿐이다.
