## 1. 앱 한 줄 소개

차 안에서 가족이 나눈 대화가 **가족의 목소리로 부르는 노래**가 되어, 목적지에 도착하는 순간 흘러나오는 가족 드라이브 앱.

---

## 2. 기획 배경

**주목한 순간: 차 안의 대화는 사라진다**
아이와 함께하는 주말 나들이·명절 귀성길에서 가족은 몇 시간씩 한 공간에 함께 있습니다. "바다 언제 나와?" 같은 아이의 질문, 휴게소에서 뭘 먹을지 다투던 이야기, 갑자기 터진 웃음처럼 그날만의 대화가 오가지만, 여행이 끝나면 사진만 남고 **차 안의 대화는 아무것도 남지 않습니다.**

**기존 경험의 한계**
- 이동 시간은 가족 모두가 '버티는 시간'이 되기 쉽습니다. 아이는 지루해하고, 운전하는 부모는 운전과 아이 달래기를 동시에 해야 합니다.
- 차량 엔터테인먼트는 스트리밍 음악·영상 중심이라 '우리 가족의 이야기'가 없고, 영상은 주행 중 이용이 제한됩니다.
- 휴대폰 앱은 차량의 기어·도착 예정 시각·주행 경로를 알 수 없어 "도착하는 순간"을 맞춰 연출할 수 없고, 운전 중에는 조작할 수도 없습니다.

**왜 해결해야 하는가**
차 안은 가족이 한 공간에 오래 함께 있는 거의 유일한 시간입니다. 이 시간의 대화를 그대로 노래로 남기면, 반복되는 이동이 매번 다른 추억이 되고, 아이는 자기 말과 목소리가 노래가 되는 경험으로 다음 드라이브를 기다리게 됩니다. 운전자는 아무것도 조작하지 않아도 됩니다.

`심사 포인트: 창의성 — Pain Point(사라지는 차 안의 대화, 지루한 이동, 운전자의 동승자 케어 부담) 정의`

## 3. 앱 주요 기능 및 차량 특화 요소

**핵심 기능**

| 기능 | 내용 |
|---|---|
| ① 대화 담기 | 출발 전 '대화 담기'를 켜면(이번 주행만, 탑승자 전원이 동의했을 때) 주행 내내 차 안 대화를 녹음한다. 화면 조작이 필요 없고, 모든 화면 위에 '대화 담는 중' 표시가 보이며, 한 번 터치로 끄면 그 주행의 대화를 지운다. 원본 대화는 노래를 만들기 시작하면 분석 직후 지운다. |
| ② 대화로 쓰는 가사 | 대화를 받아 적고 누가 말했는지 구분한 뒤(가족 등록 때의 짧은 목소리와 비교), 인상적인 말과 지나온 지명·날씨·시간대를 엮어 AI가 가사를 쓴다. |
| ③ 가족 목소리로 나눠 부르기 | AI가 작곡·노래한 곡의 보컬을 대화에서 모은 가족의 목소리로 바꿔, 구절마다 엄마·아빠·아이가 돌아가며 부른다. 목소리 음역에 맞춰 옥타브를 옮겨 반주와 키가 맞는다. 후보 3곡 가운데 리드 보컬이 가장 깨끗한 곡을 골라 부르고, 가사 없는 흥얼거림은 뺀다. |
| ④ 대화 속 한마디 | "와, 바다다!" 같은 실제 한마디를 그 사람 목소리 그대로 곡 앞·노래가 쉬는 틈·곡 끝에 넣는다. 노래 부르는 구간을 찾아 겹치지 않게 넣는다. |
| ⑤ 도착 순간 연출 | 도착 10분 전(내비 도착 예정 시각)에 생성을 시작해, 기어를 P로 바꾸는 순간 자동 재생한다. 정차 중이면 실내 앰비언트 라이트도 노래 색으로 바뀐다. |
| ⑥ 말로 하는 재생·녹음 | 차량 AI 비서(Gleo)에게 "드라이브 송 틀어줘", "둘째 응원 녹음해줘"라고 말하면 앱이 실행한다. 앱의 "말로 하기" 버튼은 차량 내 음성 인식으로 같은 명령을 받는다. |
| ⑦ 노래 보관함 | 날짜·제목·경로 그림 커버·가사·부른 가족으로 쌓이는 가족 여행 앨범. |

**차량 특화 요소**
- **차 안의 대화와 차량 데이터가 콘텐츠의 원재료**: 가족이 몇 시간씩 함께 머무는 차에서만 생기는 대화, 그리고 기어(출발·도착 판정)·내비 도착 예정 시각·주행 위치가 노래의 소재와 타이밍이 됩니다.
- **도착 타이밍**: "P단 전환 = 도착"이라는 차량 신호로, 여행의 클라이맥스인 도착 순간에 가족의 노래가 시작되고 실내 조명이 바뀝니다.
- **Pleos Connect 화면에 맞춘 UI**: 17인치 센터 디스플레이의 분할 화면(앱 영역 약 2/3)에서도 읽히도록 큰 글자·큰 버튼, 밤에도 눈부시지 않은 다크 네이비 화면, '우리 가족 노래 앨범' 홈.
- **화면을 보지 않는 경험**: 대화 담기는 켜 두기만 하면 되고, 재생·녹음은 차량 AI 비서와 음성 인식으로 합니다. 주행 중에는 재생 제어만 허용하고 설정·보관함은 정차 중에만 열립니다(CarUxRestrictions). 주행 중 화면은 정적이고 키보드 입력이 없습니다.
- **가벼운 차량 앱**: 차량 앱은 녹음·위치 기록·재생만 하고, 받아 적기·작곡·목소리 변환 같은 무거운 일은 모두 자체 GPU 서버에서 처리합니다(작곡 모델만 9.4GB이고 GPU로도 노래 1곡 전체 처리(대화 분석~목소리 변환)에 약 3.5분이 걸려 차량에서는 돌릴 수 없음. 주행 중 CPU 5% 미만 목표).

**새로운 경험**: 차 안에서 흘려보내던 대화가 "오늘 우리 가족이 함께 부른 노래"로 남습니다.

`심사 포인트: 차량특화성 — 차 안이라는 공간(대화), 주행·정차 맥락, 차량 기능(기어, 내비, 음성 비서, 조명)과의 결합`

## 4. 주요 사용 시나리오

**누가**: 초등학생 첫째와 유치원생 둘째를 둔 4인 가족
**언제**: 토요일 아침, 서울 집에서 강릉 경포해변으로 (약 3시간)

| 단계 | 상황 | 이용 흐름 |
|---|---|---|
| 준비 (정차, 한 번만) | 처음 쓸 때 | 가족·녹음 화면에서 구성원을 등록하고(호칭, 14세 미만은 보호자 동의) 각자 5초 인사말을 녹음한다. 이 짧은 목소리가 '누구 목소리인지' 알아보는 기준이 된다. 대화 녹음·목소리 변환 동의를 함께 받는다. |
| 출발 전 (정차) | 시동 직후 | 탑승자 화면에서 이번에 탄 가족을 확인하고 '대화 담기'를 켠다. 노래 스타일은 '신나는 로드트립'. |
| 주행 | 고속도로 | 기어 D로 주행 기록이 시작되고 대화가 담긴다. 화면에는 "대화 담는 중" 표시만 보인다. 둘째가 "바다 언제 나와?"를 다섯 번 묻고, 첫째는 휴게소 호두과자 이야기로 들뜬다. 운전자는 아무것도 조작하지 않는다. |
| 도착 10분 전 | 강릉 진입 | 서버가 대화를 받아 적고 누가 말했는지 구분한다. 대화 속 말과 지나온 지명(용인·평창·강릉)으로 가사를 쓰고, 작곡한 노래를 엄마·아빠·첫째·둘째의 목소리로 바꿔 구절마다 나눠 부르게 한다. |
| 도착 | 경포해변 주차 | 기어 P → 노래가 자동 재생되고 실내 조명이 노래 색으로 바뀐다. 첫 소절 직전 전주에 둘째의 실제 "와, 바다다!"가 들어가고, 구절마다 아빠·엄마·첫째·둘째 목소리로 "바다 언제 나와~"가 이어진다. 제목은 "강릉 경포해변 가는 길". |
| 그 뒤 | 숙소에서 | 보관함에서 가사·부른 가족을 보고 다시 듣는다. 돌아오는 길의 대화는 또 다른 노래가 된다. |

- 대화가 거의 없던 주행에서도, 목소리 변환에 동의한 가족은 지난 대화에서 보관한 목소리(최대 30초)로 노래를 부른다. 대화를 담지 않은 주행은 등록 때 녹음한 인사말과 차량 데이터로 노래를 만든다(AI 가수가 부름).
- 대화 담기를 켤 수 있는 조건: 이번 탑승자 전원이 대화 녹음에 동의했을 때. 등록하지 않은 사람의 목소리는 노래에 쓰지 않는다.

`심사 포인트: 창의성·차량특화성 — 누가/언제/어떻게가 구체적이고, 운전자는 주행 중 조작하지 않는다`

## 5. 개발 계획

**구조**: 차량 앱(Kotlin · Jetpack Compose · AAOS 표준 앱) + 자체 서버(Python FastAPI) + 자체 GPU AI 서비스. 차량 앱은 녹음·주행 기록·재생·화면만 맡고, AI 처리는 모두 서버가 맡는다. API 키는 앱에 넣지 않고, 가족 목소리·대화를 외부 AI 서비스로 보내지 않는다. 모든 AI 부품은 교체 가능한 어댑터 구조다.

**통신**: 차량 통신으로 자체 서버와 연결한다(공모전 안내: 퍼블릭 네트워크 사용 가능). 주행 중에는 5분마다 대화 조각(약 1.2MB, 1시간 약 14MB)을 올리고, 도착 10분 전에 노래를 맡겨 완성본을 내려받는다. 터널처럼 잠깐 끊기면 못 올린 조각을 다음 조각과 함께 올리고, 노래 만들기가 실패하면 한 번 더 시도한다. 도착할 때까지 통신이 안 되면 연결된 뒤 이어서 만드는 기능을 2차 PT 전에 넣는다.

**구현 현황 (2026-11-13 기준)**
- **대화 → 가족 목소리 노래 전체 구현**: 앱 '대화 담기'(동의 3종, 이번 주행 스위치, 화면 위 표시, 5분 단위 녹음·업로드) → 서버 대화 분석(받아 적기·화자 구분) → 대화로 가사 → 작곡 → 가족 목소리 변환·나눠 부르기 → 대화 속 한마디 삽입 → 도착 시 자동 재생 → 보관함('부른 가족').
- **Pleos Connect 에뮬레이터(2.1.0)에서 처음부터 끝까지 재현**: 데모 가족(합성 음성으로 만든 가상의 가족) 등록 → 대화 담기 → 서울→강릉 데모 주행 → 도착 10분 전 생성 시작 → 3분 47초 뒤 완성(도착 전) → P단 도착 순간 엄마·아빠·첫째가 나눠 부르는 노래 자동 재생. 가사 8줄에 대화 속 말이 들어가고 모두 불리며, 노래 앞·쉬는 틈·끝에 대화 속 실제 한마디가 들어간다.
- **실제 GPU 서버 측정 (RTX 5070 Ti 1장)**: 대화 86초·3명 → 완성 약 3.5분 (대화 분석·가사 14~38초, 후보 3곡 작곡 32~38초, 곡 고르기·3명 목소리 변환 110~148초, 믹싱 2초). 화자 구분 12/12, 받아 적기 글자 오류 5.7%, 목소리 유사도 0.64~0.81 (변환 전 AI 가수 0.17~0.22, 11월 3일 시험).
- **UI**: Pleos 화면 크기에 맞춘 리디자인 완료 (홈 '오늘의 노래'·노래 만들기 진행 단계·가족 노래 앨범, 다크 네이비·하늘색).
- 그 밖에: 차량 데이터 가사·도착 자동 재생·조명 연출, Gleo 음성 명령. 단위 테스트 앱 398건, 서버 170건, AI 서비스 31건 통과.
- 남은 일(~11/15): 시연 영상 게시 (영상 제작 완료. GitHub 저장소·APK는 공개 완료, 7번 참고).

| SDK / API | 쓰는 곳 | 현재 | 계획 |

**개인정보 설계 (구현됨)**
- **동의 3종**: 목소리 클립(필수, 누구 목소리인지 알아보는 기준), 대화 녹음(선택), 노래 목소리 변환(선택). 아동은 보호자 동의. 언제든 앱에서 끌 수 있고, 서버도 동의를 다시 확인한다.
- **대화 담기는 이번 주행만**: 탑승자 전원이 대화 녹음에 동의했을 때만 켜지고, 노래 만들기가 시작되면 꺼진다. 녹음 중 모든 화면 위에 표시, 주행 중 끄면 그 주행 대화를 기기·서버에서 삭제. 등록하지 않은 사람의 목소리는 노래에 쓰지 않는다.
- **원본 대화는 남기지 않는다**: 기기에서는 올리는 즉시, 서버에서는 분석 직후(실패해도) 삭제. 받아 적은 글은 저장하지 않는다.
- **가족 목소리는 그 가족의 노래에만**: 참고 목소리(최대 30초)는 변환 동의 철회·구성원 삭제 시 즉시 삭제. 외부 AI 서비스로 보내지 않고, AI 모델 학습에 쓰지 않는다. 받아 적기·가사·작곡·변환 모두 자체 GPU 서버.
- 개인정보 처리방침·위치정보 이용약관 페이지 제공 (서버는 좌표를 저장하지 않음).

## 6. 기대효과 및 발전 가능성

**사용자 가치**
- 아이: 자기 말과 목소리가 노래가 되는 경험. 지루한 이동이 '노래를 만드는 시간'이 된다.
- 운전하는 부모: 조작할 것이 없고, 동승자 케어 부담이 줄어든다.
- 가족: 차 안의 대화와 목소리가 노래로 쌓여, '가는 길'까지 기억하는 가족 앨범이 생긴다.

**타깃 고객**
- 1차: 미취학·초등 자녀를 둔 3~5인 가족. 주말 나들이, 명절 귀성처럼 반복되는 장거리 이동이 있다.
- 2차: 손주와 함께 이동하는 조부모, 커플·친구 여행, 렌터카 여행객.

**예상 MAU** (아래 비율은 가정)
- 현대차그룹은 2030년까지 현대·기아·제네시스 약 2,000만 대에 Pleos Connect를 적용할 계획이다 (현대차그룹 보도자료, 2026-04-30). 첫 차종은 더 뉴 그랜저(2026-05 출시)이고 북미·유럽·인도로 넓힌다.
- 국내 출시 2년차 가정: 탑재 차량 100만 대 × 자녀 동반 가족 차량 30% × 앱 설치 10% × 월 1회 이상 사용 50% ≈ **MAU 약 1.5만**.
- 같은 비율로 2030년 2,000만 대면 **MAU 약 30만**. 2차 타깃(조부모·커플·렌터카)을 더하면 더 커진다.

**Retention**
- 대화는 매번 다르므로 노래도 매번 새로 만들어진다. 주행을 시작하고 대화 담기만 켜 두면 되어 별도 습관이 필요 없다.
- 보관함에 쌓이는 '우리 가족 목소리 앨범'이 다음 이동의 동기가 된다.
- 목표: 30일 재사용률 40% (가정, 2차 PT 전 시험 사용으로 확인).

**향후 확대 계획**
- **개인 맞춤 목소리**: 대화가 쌓일수록 구성원별 목소리 모델을 다듬어 더 닮게.
- **가족 합창 후렴**: 후렴은 온 가족 목소리를 겹쳐 합창으로.
- **장소 기억 앨범**: 같은 목적지를 다시 가면 지난 노래에 이어 2절을 만든다.
- **연간 리캡**: 1년 동안의 드라이브 송 메들리.
- **여행·관광 연계**: 휴게소·관광지 정보를 가사 소재로, 지자체·관광지와 "지역 노래" 제휴.
- **수익 모델**: 기본 무료(월 몇 곡) + 프리미엄 구독(무제한, 개인 맞춤 목소리, 고음질), 관광·렌터카 제휴.
- **서버 비용**: 노래 1곡에 GPU 약 3.5분(데모 기준: 대화 86초·3명, RTX 5070 Ti 약 210초). 클라우드 GPU(RTX 4090, 시간당 0.89달러, RunPod 2026-11 기준)로 계산하면 곡당 약 0.05달러(1달러 1,400원이면 약 73원)다. MAU 1.5만이 월 4곡씩 만들면(가정) 월 약 3,100달러로, 곡 수에 비례하므로 무료 곡 수로 조절한다.

`심사 포인트: 사업성 — 타깃 명확성, MAU·Retention 근거, 확대 경로`
